# Implementation Worklog

## Status

Mode: product

Mesh FX Lab is a working Toolcraft product that applies a complete GPU effects stack to a custom built-in ring or an uploaded GLB, embedded glTF, or OBJ model. It supports left-button camera orbit plus a six-axis orientation gizmo with Blender-style click-to-snap and free point drag, and intentionally has no timeline.

## Decisions

### Renderer

- Decision: Use an independently tuned Three.js WebGL scene with a locally generated six-panel PMREM environment, followed by separate stylized, post-processing, adjustments, and output passes.
- Reason: The product needs mesh depth, lighting, model import, dense pixel patterns, and live post-processing that DOM, SVG, and Canvas 2D cannot reproduce efficiently.
- Evidence: `src/app/renderer/three-effects-engine.ts`, `effect-shaders.ts`, `effects-bloom-pass.ts`, `model-loader.ts`, browser WebGL checks for all ten stylized branches and six post branches, and typed renderer coverage in `src/app/app-performance.ts`.

### Timeline

- Decision: Omit the Toolcraft timeline and video export.
- Reason: The user explicitly said the timeline is not needed; Film Grain dynamic noise is autonomous decorative output with no transport, duration, or export-at-time behavior.
- Evidence: `appSchema.panels.timeline` is omitted, browser acceptance finds no playback controls, and `appTransferMode.animationIntent` declares autonomous no-transport behavior.

### Layers

- Decision: Omit the Layers panel.
- Reason: The app edits one 3D source and one composited product output, with no user-facing reorder, visibility, grouping, or multi-entity layer workflow.
- Evidence: `appSchema.panels.layers` is omitted and source replacement is handled by the built-in `fileDrop` control.

### Controls

- Decision: Expose the Mesh FX control set through Toolcraft built-ins, except for a true custom `orientationGizmo` control backed by the schema target `view.orbit`.
- Reason: Select, segmented, slider, switch, color, actions, and fileDrop cover the ordinary settings. The closest built-in `vector` cannot express six depth-sorted camera axes, click-to-snap, Blender-style free point orbit, or a viewport-fixed editing handle.
- Evidence: `productControlSections`, `starterControlSectionInventory`, `orientation-gizmo-control.tsx`, and the custom-control/canvas-handle acceptance rows cover source media, view orientation, eleven stylized modes, adjustments, six post effects, Background, and Image Export.

### Export

- Decision: Keep Toolcraft-native still-image delivery with PNG/JPG format and 2K/4K/8K resolution settings behind the sticky Export PNG action.
- Reason: This is a still editor with an explicitly omitted timeline; the export must preserve selected image resolution, background inclusion, and transparency behavior.
- Evidence: `src/app/panel-actions.ts`, `renderEffectsExportCanvas`, `createToolcraftPngExportCanvas`, and browser decoding of a 2K image with a 2048px long edge.

### Performance

- Decision: Render the full fitted preview at browser DPR multiplied by the selected Resolution scale, keep preview-logical shader resolution separate from physical backing pixels, cache the full-quality MSAA scene independently from post uniforms, keep post targets single-sampled, fuse neutral/output-only passes into the final active shader, cache the pre-grain result for dynamic Film Grain, and suspend non-essential grain work during viewport interaction.
- Reason: The previous 720px/DPR caps made Resolution ×2 mostly declarative and visibly soft, while the first full-resolution composer repeated the scene raster and redundant full-screen passes for every control frame. The current path preserves every selected backing pixel and effect formula while avoiding work that cannot change the result.
- Evidence: `EffectsCanvas`, `ThreeEffectsEngine`, `ExternalTextureComposer`, `EffectsBloomPass`, exact backing-buffer browser checks, focused pass/invalidation tests, and the agent-browser performance checkpoint at a 4800×2700 backing buffer.
